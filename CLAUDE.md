# Working on this repo (notes for Claude Code and other AI assistants)

## What this is
A Windows Forms tool that builds Crusader Kings II character portraits from the user's own CK2 install. It is a fork, and **all of the fork's changes were written by AI (Claude)**. The older code underneath is human-written (see CREDITS.md). Keep that statement true and prominent in the README, the About box, CREDITS.md and commit messages.

## Build, test, install
- Needs the .NET 10 SDK. Build: `dotnet build src/PortraitBuilder.WinForms -c Release`. Tests: `dotnet test test/PortraitBuilder.Tests`.
- Only the WinForms and Tests projects are built and tested. `PortraitBuilder.Online` (Azure Functions) did not build with current tools; leave it alone unless asked.
- `scripts/install-local.ps1` builds, tests and copies the result over the installed copy named in `.local/install-dir.txt` (git-ignored). It never commits.
- Keep the repo and the install folder at short paths. Windows refuses to open a program whose full path passes 260 characters.

## Workflow for every change
1. Make the change, build, test, and look at it running.
2. Run `scripts/install-local.ps1` so the user's installed copy matches.
3. Tell the user what changed and what was not checked, and **ask before committing or pushing**.
4. Only after they confirm: commit (message says it was written by an AI assistant, ends with the `Co-Authored-By: Claude ... <noreply@anthropic.com>` line) and push to `origin` (the user's fork). `upstream` is scorpdx/portraitbuilder; do not push there.

## Where things are
- `src/PortraitBuilder.WinForms/UI/PortraitBuilderForm*.cs`: the main window, split by job: `.cs` (state, history, features), `.Layout.cs` (building the window), `.Picker.cs` (picture tiles, roles, which tiles get drawn), `.Saved.cs` (Keep and last portrait), `.Export.cs` (More menu, export, batches, themes, DLC window), `.Names.cs` (race names, hover cards, right-click menu), `.Style.cs` (looks, history strip, settings).
- `Controls.cs`: Chip, TabStrip, HoverRow, IconTile, TilePicker. `AboutDialog.cs`, `ShortcutsDialog.cs`.
- The drop-down boxes for features still exist but are never shown; they hold the values. Tiles are the interface.
- `src/PortraitBuilder.Shared/Engine`: rendering. `assets/branding`: logo and icons, regenerated by `make-branding.ps1`.

## Rules
- Do not add screenshots, extracted sprites or any other Paradox art to the repo. Do not search for or download CK2 art; the tool reads the user's own install.
- Do not download or run unverified executables. Ask before any download.
- Settings files (`settings.txt`, `saved.txt`, `gamedir.txt`, `log.txt`) live next to the exe and are git-ignored.

## Testing tips (UI)
- No UI test framework. Verify by running the app. Screenshots: capture only the app's own window (PrintWindow), never the whole screen, and make the capturing process DPI-aware or the image is cropped.
- UI Automation can invoke buttons (Chip and IconTile are Buttons). Pop-up menus close if the app is not the foreground window, so menu tests can be flaky on a busy desktop.
- Tiles draw on a background thread; wait a few seconds after a change before capturing.
